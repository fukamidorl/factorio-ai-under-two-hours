# Factorioの扱い方と使用ツール

[人間向けREADME](../../README.ja.md) · [AI操作手順](AI_OPERATIONS.md) · [English](../en/METHOD_AND_TOOLS.md) · [简体中文](../zh-Hans/METHOD_AND_TOOLS.md)

## 配布版を動かす

Windows 64ビット、インストール済みの **Factorio 2.1.25**、Python 3.11以降を用意する。検証したFactorioはSteam版のビルド88022。2.1.25を別の場所に入れて使う場合は、各起動コマンドに `--factorio "D:\Games\Factorio\bin\x64\factorio.exe"` を追加する。 [Factorio公式の旧版アーカイブ](https://www.factorio.com/download/archive/2.1.25)

1. 配布ZIPを展開し、`run_route.py` があるフォルダで PowerShell を開く。`check` でFactorioの版と配布ファイルのハッシュを確認する。試走を起動すると、Factorioが `world/map-gen-settings.json` から開始セーブを生成する。
2. **画面を見たい場合**は下記の `visible` を使う。Steamがカスタム引数を確認する場合は、今回の `runs/watch-01/` の設定・MOD・セーブを指していることを確かめて「続行」を選ぶ。Factorioをすでに開いている場合は、必要なセーブを保存して閉じてからこの試走を起動する。
3. 開始後は採掘・発電・研究などのゲーム画面を観戦できる。画面の起動直後はキャラクター視点で、その後カメラが工場を巡る。配布版の画面設定とカメラ見出しは日本語。打ち上げ時は等速になり、勝利画面で結果を確認できる。
4. **画面なしで通し検証**するなら `headless` を使う。内部ではFactorioの `--test-save` を起動し、衛星発射と宇宙サイエンス1,000個の着荷を判定する。PowerShellの処理が終わったら `report` で結果を読める。

~~~powershell
py -3 -X utf8 .\run_route.py check
py -3 -X utf8 .\run_route.py visible watch-01
py -3 -X utf8 .\run_route.py report watch-01
~~~

~~~powershell
py -3 -X utf8 .\run_route.py headless verify-01
py -3 -X utf8 .\run_route.py report verify-01
~~~

試走名は毎回新しくする。画面ありを途中で終えるときは、必要ならそのウィンドウからセーブして閉じる。画面なしを中断する場合は PowerShell で `Ctrl+C`。ランチャーがその試走用に起動したプロセスを終了する。`report` は保存済みのゲーム内ログを読むので、中断後には最後に記録した段階が表示される。利用者が観戦しているときは勝利画面を残し、着荷まで画面ありで観測する場合は勝利画面から続行する。ゲーム内ログは `runs/<試走名>/script-output/` に出る。画面ありでは、サイロと発射のスクリーンショットも同じ場所に保存される。

## ロケットまで動かした専用MOD

**`first-rocket-route-check` 0.1.0** は、このシードの衛星打ち上げ用に作ったLua MOD。ランチャーは基本ゲームで `runs/<試走名>/input-world.zip` を生成し、生成ログを `world-generation.log`、セーブのSHA-256を `run.json` に記録する。その後、`mod/` のMODを試走用のフォルダへコピーし、選んだモードに合わせて `trial-policy.lua` を作る。配置・研究順は `design.lua`、画面のカメラは `watch.lua` にある。 [専用MODのソース](../../mod/first-rocket-route-check_0.1.0/) · [ランチャー](../../run_route.py)

- **初動**は、初期演出後に歩行・採掘・クラフトをLuaから指示する。初期所持品はゲームが与える燃料式掘削機、石の炉、木材。設置で機材を消費する。
- **初期蒸気以降**は、ゲーム内で採取・製造したものをLua側の在庫表に集め、炉・組立機・発電・研究所へ直接配給する。Luaが中間在庫を管理し、区画間の一部の搬送や施工・整地を補助する。実物の設備を消費して衝突を確認した上で設置し、研究をキューに入れる。
- **終盤**は、採掘・精錬・製造・発電・研究がFactorio本体で進む。Luaが生産済みの衛星をサイロに積み、自動発射設定を有効にして、発射イベントと降着パッドへの着荷を記録する。

人力走と比べるときは、今回の記録にLuaによる施工・配給とゲーム速度設定が入ることを明示する。

## 取得候補の実績

Factorio 2.1.25の基本ゲームで、このルートの進行から狙える主な実績。配布版の試走では発射・生産・設備を記録した。 [2.1.25の実績定義](https://github.com/wube/factorio-data/blob/2.1.25/base/prototypes/achievements.lua)

| 実績 | 条件 |
| --- | --- |
| 自動化せよ！ | 組立機1を設置する。 |
| エコ反対 | 原油処理の研究を完了する。 |
| 大量生産 1 | 電子基板を累計10,000個生産する。 |
| 鮭をスモークしてくれ、朝食までには戻る | ロケットを打ち上げる。 |
| 雑談する暇はない | ゲーム内時間15時間以内にロケットを打ち上げる。 |
| スプーンなんてない | ゲーム内時間8時間以内にロケットを打ち上げる。 |
| ずっと蒸気 | ソーラーパネルを設置せずにロケットを打ち上げる。 |
| 弾丸の雨 | レーザータレットを設置せずにロケットを打ち上げる。 |

配布版の画面なし試走では、操作開始からゲーム内時間1時間50分18秒で発射し、電子基板を130,478個生産した。ソーラーパネルとレーザータレットの設置はともに0基で、衛星の材料にはソーラーパネル100枚を使った。 [配布版の試走記録](../../reference/package_verification.json)

**Steamで確認済み**の「スプーンなんてない」は、旧シード `210539101` の改訂試走で2026年11月22日21:02（日本時間）に解除された。Factorio 2.1.24で勝利直前のセーブを専用MODなしで再開し、ゲーム内5:49:24で勝利した回に当たる。同日に解除された関連実績も確認した。 [取得日時と試走の照合記録](DEVELOPMENT_HISTORY.md)

Factorioの標準仕様では、専用MODを有効にしたプレイの実績はゲーム内のMOD用実績に記録される。Steam実績を狙う場合は、実績が有効なMODなしのフリープレイで条件を満たす。敵や汚染の設定を標準より弱めると、一部の時限・設備制限の実績が無効になる。 [Factorio Wikiの実績条件](https://wiki.factorio.com/Achievements#Disabling_achievements)

打ち上げ後に「物流ネットワーク禁止」も狙うなら、アクティブ供給チェスト・バッファーチェスト・要求チェストを設置せず、着荷した宇宙サイエンスパックを使う研究を完了させる。

## 開発・検証で使ったもの

| ツール | 使用した場面 |
| --- | --- |
| ChatGPT Codex・GPT-6.2 Sol | 工程の設計・実装、試走ログの分析、ドキュメント化。利用者の説明では調整中は超高（`xhigh`）とMax（`max`）を使用し、最終段階はMax。 |
| Computer Use | Windowsのゲーム画面・Steam起動ダイアログの確認、画面付きデモでの確認。鉄板デモで移動・採掘の長押しが必要になった際は、Windows向けの入力補助プログラムを使った。 |
| Factorio LLM Use 0.1.1、`uv`、MCP、ローカルRCON | Factorio 2.1.24との初期接続試験で鉄鉱石を採り、鉄板1枚を作って回収した。汎用的な操作手段を確かめた段階。 [Factorio LLM Use](https://github.com/Tsyklop/factorio-llm-use) |
| `visible-first-iron-demo` 0.1.0 | 2.1.24の画面付き鉄板デモ専用。炉の材料欄を `defines.inventory.crafter_input` に修正した試走では、開始から1,310ティックで手荷物に鉄板1枚、炉の出力に0枚を確認した。 |
| `first-rocket-route-check` 0.1.0、Python、PowerShell | 現行の新規マップから衛星発射まで。画面ありはFactorioウィンドウで実行し、画面なしは本体のテストモード。先行の統合試走では途中から同じセーブをローカルサーバーに引き継いで着荷を測った。 |
| 公開RTAの動画・セーブ、Python、Git | 人力走の工程や流量との比較、ログの集計、配布ファイルのチェックとZIP化に使用。 [開発の時系列](DEVELOPMENT_HISTORY.md) |

再現に必要なものは、インストール済みのFactorio、Python、配布物。Computer UseとFactorio LLM Useの接続環境は、それぞれ開発・検証で使った手段として記録している。

## 開発時の週間利用枠

利用者の概算では、プロジェクト作業中の **ChatGPT Pro 100** の週間利用枠は、残量表示が **約100%から約75%** に動いた。**約25パーセントポイント**はその表示上の差。観測の正確な時刻、同じ週枠内の他の利用内訳、プロジェクト単独のトークン数・費用は記録していない。ゲーム内タイムやローカル再生の所要時間とは計測単位が異なる。 [環境と利用量の記録](../../reference/run_environment.json)

利用枠の消費はモデル、推論設定、処理する文脈やツール使用によって変わる。この値は当時の開発作業の目安として扱う。 [OpenAIの利用枠説明](https://learn.chatgpt.com/docs/pricing#usage-limits)
