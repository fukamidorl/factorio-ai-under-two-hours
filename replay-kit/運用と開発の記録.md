# 固定再生の運用と研究開発の記録

[再現キットの入口](README.md) · [工場全景の撮影記録](evidence/visible-capture.json)

設計、実装、試走分析、文書作成の大半をChatGPT Codexが担当した。ユーザーは目標と比較条件を決め、人力RTAの資料を提示し、増産・研究中の並行施工・箱とインサータによる投入などを提案した。実走画面とSteam実績の確認にも参加した。今回の固定再生は、PythonのランナーとFactorio用の専用Lua MOD `first-rocket-route-check` で実行する。画面の確認やSteamの操作ではComputer Useを使った。

## AIの権限と役割

| 担当する作業 | 用意するもの | 終了条件 |
|---|---|---|
| 固定再生と結果報告 | ターミナルを使えるAIまたは実行者。入口は `operate.py replay` | 版・ビルド・シードと照合結果を記録し、`matched`・339,287ティック・1,000個を確認 |
| 監督と復旧 | `operate.py status`、実行ID、結果ログ | 進行中は元のIDを追う。版、入力、途中証拠、着荷欠損を確認し、必要なら新しいIDで再走 |
| ログ診断のみ | `operate.py practice` の出力か、人が取得した状態JSON | 状態と必要な証拠を言語化。模擬問題の期待値は回答前に渡さない |
| 改善実験 | コピーした基準ルート、仮説、単一変更、計測表 | 研究の前倒しが着荷まで残るかを通しで確認。資材と電力への影響も控える |

改善実験では `4263722700_工数改善/基準ルート` のコピーを使う。変更ファイルをマニフェストに反映し、コピーで `python run_route.py headless candidate-01` を実行する。入力マップのハッシュを確認し、`script-output/through-latest.json` とゲーム内イベントを保存する。採用後の固定再生と候補の比較は、それぞれ使った基準を添える。複数条件を一度に変える場合は、個別に測定した後で通しを試す。

モデル比較では、製品・モデル・推論設定、ツール権限、着荷までの完了数、誤判定、介入回数と実時間を記録する。実機の検証環境はWindows 11、Core i5-12450H、メモリ16 GiB、RTX 3050 Ti Laptop。画面付きの操作やSteamの照合ではComputer Useを使用した。 [実行環境と使用ツール](evidence/environment.json) · [初期の模擬判定](evidence/ai-operation-checks.json)

## 旧配布版と公開候補の比較

旧配布版に掲載した着荷1:50:27は操作開始を起点としたゲーム内時間。今回の比較は、100分挑戦時と公開候補で使用した初期マップを照合し、ワールド開始を起点とした。100分挑戦時の着荷 **1:50:50.017** から今回の **1:34:14.783**（339,287ティック）まで、59,714ティック（16分35.233秒）短縮した。今回のロケット上昇完了は **1:34:05.300**。直前の研究所単独案の着荷1:34:17.067からは137ティック（2.283秒）短縮した。 [起点を揃えた比較](evidence/timing-history.json) · [直前の基準の再走](evidence/replays.json)

55%で鉄板配分を変更した案は、旧併用案と研究完了・衛星積み込みが同じ時刻だった。サイロ研究完了時の制御基板は988個から1,034個に増え、サイロの制御基板待ちは9.400秒から0.483秒に減った。鉄板を同量生産した2分区間では電子基板が885個増え、鋼材生産が140枚減った。同時点の鋼材の共用在庫1,441枚と打ち上げ向けの予約在庫1,025枚は確保できた。研究所のサイエンスパック在庫・欠品の66回の観測は旧併用案と一致した。研究終盤には、同時点の硫酸の共用在庫が305から45まで減り、供給の余裕が小さくなった。 [資材と時刻の実測](evidence/iron-allocation-55-comparison.json)

最速候補の2回は、初期マップと実行MODのチェック、着荷までのイベント223件、生産・消費、最終状態が一致した。公開用に別展開したキットの再生も別に記録した。掲載した工場全景と1:36:25.900の着荷は、撮影用ルートの実走結果。手動発射は同梱の準備済みセーブから操作する。 [ヘッドレスの公開用検証](evidence/release-verification.json) · [画面付きの実地記録](evidence/visible-capture.json) · [手動発射の確認](evidence/neutral-manual-handoff.json)

## 人力RTAと比較するときに見る箇所

序盤はキャラクターの移動や採掘をスクリプトで指示する。増産段階に入ると、`factory.lua` の `put` が設置可否と施工資材を確認して座標に設備を置く。配置の候補はゲーム内60ティックごとに評価され、一度の評価で工数上限に収まる複数の施工が可能。30ティックごとの `service` は、設備からの回収、実インベントリへの供給、研究選択などを行う。水の回収は5ティック、流体供給は15ティックごと。これらはゲーム内の間隔で、リアルタイムのクリック頻度や人の反応速度を表す値とは測定条件が異なる。 [固定再生のLuaコード](4263722700_工数改善/基準ルート/mod/first-rocket-route-check_0.1.0/factory.lua)

同じ工場の距離でも、共有在庫の配給にはキャラクターの往復やベルトの搬送時間がかからない。人力側から取り入れやすいのは、初期施工材の確保、研究と増産の並行、製造設備の隣接、研究所への複数方向の供給。公開候補のヘッドレス再生ではロケットの上昇完了と着荷に569ティック（約9.48秒）の差がある。比較表には到達点・ゲームの版・補助操作・計時方式を添える。 [人力での段階的な工場づくり](https://rtain.jp/game-title/factorio/) · [Zasparの標準設定走](https://www.speedrun.com/factorio/runs/yvk04e8m) · [TAS作者の制作解説](https://www.reddit.com/r/factorio/comments/1rtsdca/toolassisted_speedrun_for_factorio_finishes_the/)
